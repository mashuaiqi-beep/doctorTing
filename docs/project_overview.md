# 医疗问诊分诊 Agent 项目设计

## 1. 项目定位

这是一个面向 Agent 实习和求职展示的小型医疗问诊分诊项目。

项目目标不是做完整医院系统，也不是直接做医疗诊断，而是做一个可运行的 Agent Demo，展示以下能力：

- 多轮问诊
- 风险识别
- 结构化输出
- 大模型调用
- 后端工程分层
- 后续扩展到 RAG、LangGraph、Tool Calling

核心场景：

用户输入一句自然语言症状描述，例如：

```text
我发热两天了，还一直咳嗽
```

系统需要完成：

1. 提取症状
2. 判断当前信息缺口
3. 给出下一轮追问
4. 识别明显高风险信号
5. 输出结构化结果

## 2. 项目目标

### 2.1 业务目标

做一个最小可演示的医疗问诊分诊 Agent，支持：

- 首轮症状采集
- 初步风险判断
- 多轮追问
- 最终分诊建议

### 2.2 技术目标

通过这个项目练习并展示：

- `FastAPI`
- `Pydantic`
- 分层设计
- 大模型 API 调用
- Prompt 设计
- 风险规则设计
- 后续接入 `LangGraph`
- 后续接入 `RAG`

### 2.3 简历目标

项目最终应能支持你在简历和面试中表达：

- 我做过一个真实可运行的 Agent 项目。
- 我会把接口层、业务层、模型层拆开。
- 我会用大模型做结构化信息抽取。
- 我知道医疗场景需要规则兜底，不能只靠模型自由输出。

## 3. 功能设计

### 3.1 MVP 功能

当前 MVP 包含 3 个接口：

- `POST /triage/start`
- `POST /triage/continue`
- `POST /triage/evaluate`

### 3.2 `/triage/start` 职责

输入用户首轮主诉，输出：

- `session_id`
- `symptoms`
- `missing_fields`
- `next_question`
- `risk_level`
- `red_flags`

### 3.3 `/triage/continue` 职责

在已有会话基础上继续追问，输出：

- 更新后的摘要
- 下一轮问题
- 是否需要继续追问

### 3.4 `/triage/evaluate` 职责

在问诊信息相对充分时，输出：

- 病情摘要
- 风险等级
- 推荐科室
- 分诊建议
- 参考知识来源

## 4. 技术设计

### 4.1 目录设计

```text
app/
├── api/        # 路由接口层
├── schema/     # 请求体与响应体
├── service/    # 业务服务层
├── core/       # 配置、Prompt、规则
├── agent/      # 后续 LangGraph 工作流
├── model/      # 后续数据库模型
├── tools/      # 后续工具调用
└── main.py     # 应用入口
```

### 4.2 分层职责

API 层：

- 接收 HTTP 请求
- 做请求参数绑定
- 调用 Service
- 返回标准响应

Schema 层：

- 定义请求体
- 定义响应体
- 约束接口数据格式

Service 层：

- 组织业务流程
- 调用大模型服务
- 调用风险控制服务
- 后续调用数据库和检索服务

LLM Service 层：

- 封装大模型 API 调用
- 管理 Prompt
- 解析结构化输出

Risk Control 层：

- 处理红旗症状
- 做规则兜底
- 保证医疗输出更安全

## 5. 当前主流程

`/triage/start` 当前流程：

1. 用户输入症状。
2. API 接收 `user_input`。
3. `TriageService` 调用 `LLMService`。
4. 大模型返回症状、缺失信息、追问内容。
5. `TriageService` 调用 `RiskControlService`。
6. `TriageService` 调用 LLM 做红旗症状语义识别。
7. 合并规则和 LLM 风险结果。
8. 创建会话并返回标准 JSON。

## 6. 风险判断设计

当前方案是：

- 规则兜底
- LLM 语义判断
- 两者合并结果

规则层适合命中明确高危词，例如胸痛、胸闷、呼吸困难。LLM 层适合识别口语化表达，例如“喘不上气”“胸口像被压住”。

合并策略应保持保守：只要任一侧判断为高风险，最终风险等级就是 `high`。

## 7. Prompt 设计

Prompt 的目标是：

- 从用户输入中提取症状
- 找出缺失的关键信息
- 给出下一轮追问
- 以 JSON 格式返回
- 限制模型不要诊断、不要开药

Prompt 统一放在 `app/core/prompt_manager.py`，避免散落在业务代码中。

## 8. 项目边界

这个项目不是：

- 医疗诊断系统
- 处方系统
- 医院 HIS/EMR 系统

这个项目是：

- 医疗问诊分诊 Agent Demo
- 一个偏工程展示和求职展示的项目

重点是：

- 架构清晰
- 主链路真实可跑
- 能展示 Agent 思路
- 能说明医疗安全边界

## 9. 最终展示目标

项目达到合适阶段时，应能对外展示：

1. 用户输入一句症状。
2. 系统自动提取症状。
3. 系统发现缺失信息并追问。
4. 系统给出风险等级。
5. 系统输出结构化分诊结果。
